# Green UI redesign implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Apply the approved forest, emerald, mint and amber design to web and desktop.
**Architecture:** Preserve Razor handlers and WPF bindings/events; extend shared presentation resources and public page markup. Keep existing font declarations unchanged.
**Tech stack:** ASP.NET Razor Pages, CSS, local SVG, WPF XAML.
**Spec:** User requirements in this conversation, approved 2026-11-25; no further approval requested.

## Constraints
- Preserve all existing font sizes, business logic, APIs, database structures and workflows.
- Preserve uncommitted user changes; baseline saved in the system temporary directory.
- Public landing sections: Home, About, Features, Contact; Login/Register remain outside app shell.
- No invented contact details or nonfunctional contact form.
- Maintain light/dark themes, keyboard focus, mobile navigation, table scrolling and printing.

## Tasks
- [x] Web presentation: add green theme, local pharmacy illustration, landing sections and navigation; refresh authentication and shared internal shell.
- [x] Desktop presentation: update shared resources, login, shell, cards, tables and form surfaces; keep events and font declarations intact.
- [x] Verify: build both projects, run existing tests, compare baseline font declarations/bindings, inspect rendered pages at desktop/mobile sizes and desktop XAML rendering where available.

## Review focus
Authenticated users opening login/register must not get sidebar. Password reveal must fire once. Dark theme must retain readable controls. Narrow viewports must retain all actions. Existing invoice print layout must remain usable.

## Execution notes
Working in the supplied checkout to retain the user's uncommitted font changes. Presentation-only changes use builds, baseline checks and rendered inspection rather than implementation-mirroring unit tests.


## Verification results
- Both production projects compile using a separate output directory (normal output is held by an existing application process).
- Existing suite: 12 passed, 0 failed.
- Headless browser: 20 routes return 200; login works; password masking/reveal works; authenticated Login/Register have no sidebar.
- Responsive checks: no document overflow at 375, 760, 980 and 1440 pixels for public/authentication and representative internal pages.
- Light/dark screenshots inspected; dark settings were changed only in a disposable test database.
- WPF render harness: login, shell, all nine additional views and small-window layouts rendered in both themes.
- Font declarations match the saved user baseline. Computed web font sizes match with/without the new stylesheet on dashboard, authentication and medicine form pages.
- Original WPF names, bindings and event handlers remain present. No business code changed; App.xaml.cs edits affect theme brushes only.
- Review findings addressed: dark hero CTA contrast and finite desktop grid viewport. Mobile sidebar overflow corrected after headless reproduction.
